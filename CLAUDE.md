# Working agreements

## Writing style

**Never use em dashes (—) or en dashes (–).** Not in chat, not in code comments, not in
commit messages, and not in any drafted email, document or deliverable.

The reason is practical, not aesthetic: the repo owner cannot type them on his
keyboard, so any em dash Claude writes into a draft becomes a character he cannot
match when he edits the text himself. A document with a mix of both looks careless
to the recipient.

Use instead, in rough order of preference:
- a comma, when the aside is mild
- a colon, when what follows explains what came before
- parentheses, for a true aside
- a full stop and a new sentence, which is usually the best fix
- a hyphen (-) only where a hyphen is genuinely correct (compound modifiers)

This applies to existing files too: when editing a document that already contains
dashes, replace them rather than preserving them.
